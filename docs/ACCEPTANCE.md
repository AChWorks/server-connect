# Acceptance and evidence contract

**Goal:** Prove the delivered features of [PROJECT-SPEC.md](PROJECT-SPEC.md) on exact source, build, package and network environments. This document owns the **test matrix and proof threshold**; Issues own unfinished work and PR/CI/Release artifacts own particular runs and verdicts.

## Evidence rules

- Identify the exact commit, release/archive hash, official upstream sing-box version, OS/kernel/architecture, actual active profile path (without secrets), relevant host baseline, required duration, results and rollback evidence.
- Record **PASS / FAIL / NOT_RUN / UNSUPPORTED** explicitly. Never infer a real foreign VPN path from a healthy sing-box process, Direct internet request, code test, Docker loopback, a Windows client or synthetic network outage.
- Evidence levels differ: **source/unit**, **disposable installed Linux guest**, **independently observed real Iran/foreign field path**, **authenticated distributable artifact**, and **separately authorized production rollout**. A lower level never implies a higher one.
- Privileged/network-affecting implementation needs exact-candidate fault and safety tests and **fresh author-separated high-assurance review**. Production server changes and publication require their own applicable Owner approval. No real customer server is an initial test host.

## Registry-country data boundary

A pinned **DB-IP Country Lite geolocation estimate (October 2026)** is bundled for offline read-only inspection via `smart-routing-data`, with independently tested canonical IPv4/IPv6 prefixes, sorting, overlaps, special-purpose rejection, strict metadata, a pinned source-archive digest and a **separate source-code pin of the exact derived-prefix digest** (not merely a self-rehashed JSON member). **Attribution: [IP Geolocation by DB-IP](https://db-ip.com), licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).** Project modifications: extracted IR country-code records from DB-IP Lite CSV and converted source IP intervals into deterministic CIDR lists. DB-IP Lite is a reduced-coverage, imperfect estimate of IP country, not proof of the current origin, reachability or route of any packet; therefore `safe_for_geographic_routing` and `activation_ready` remain **false**. A reproducible local archive generator verifies exact pinned source bytes (including a checksum cross-check against the published mirror) and an offline installed Debian 13 guest verifies that inspection never changes network state. A source hash is not a publisher signature, and checking one source never establishes the precision of all its country assignments. Trustworthy update, rollback, rule precedence and real Iranian/foreign field route validation in the release matrix remain open.

The **development-only** TUN candidate compiler rejects IPv4 operator Direct CIDRs broader than /24 and more than 64 distinct /24 Direct blocks (with at most 128 total operator exceptions and 64 extra protected entries), plus synthetic domestic IPv4 CIDRs broader than /8, nonpublic/reserved ranges, overlaps, over 10,000 prefixes, or aggregate coverage exceeding 2^25 addresses. The admission check also rejects **full-CIDR intersections** with a fixed, offline, conservative IANA IPv4 special-purpose inventory (registry updated 2025-10-09), including a public-starting /8 that contains RFC1918 or link-local space, deprecated 6to4 relay anycast and globally reachable special-use service blocks. Public neighbors remain valid; the included IPv4 multicast exclusion is outside the unicast registry. This inventory needs deliberate re-review when IANA allocations change and does not establish geographic identity. The full pinned DB-IP Lite IPv4 list is representable **only if explicitly supplied** as development input; neither these numerical safeguards nor the independent digest pin authenticate geographic attribution or allow automatic Iran Direct routing. Positive and negative compiler tests plus actual disconnected-guest generator rejection tests guard against a near-global or many-prefix Direct bypass. The compiler additionally accepts bounded, explicitly configured exact/suffix **VPN-only** domain exceptions and uses native sing-box 1.14 HTTP Host/TLS SNI sniffing for TCP, with protected and explicit IP/CIDR operator exceptions taking precedence. The isolated installed-host harness tests synthetic exact/suffix HTTP Host VPN overrides of otherwise Direct IPv4 addresses, verifies raw-IP paths are unchanged, and checks an independent native Direct-leak witness. Sniffed Host/SNI values are client-controlled and do **not** authenticate DNS-to-IP correlation; therefore **domain Direct is explicitly rejected** until trustworthy domain/IP binding and route safety are implemented. This is not imported trusted SRS lists, automated Iran Direct, IPv6 coverage, production activation, or release evidence. An application-supplied Host header must never create an unapproved Direct bypass.

**Historical candidate containment:** an earlier unpublished PR #57 iteration temporarily embedded RIPEstat Country Resource List data, whose service terms prohibit repackaging without written permission. That dataset was replaced with explicitly redistributable CC BY 4.0 DB-IP Lite data **before merge**; never reintroduce the RIPEstat payload into distributable artifacts without explicit written rights. Prior public Git objects may remain accessible by immutable SHA even after branch-history replacement.

## Existing tests and their limits

The repository already includes **valuable disposable-host evidence and regression harnesses**, but **not** proof of production TUN or public release. Keep authoritative test procedures in the actual sources instead of copying their full logs or thousands of assertions into Markdown:

Both lanes require opposite, missing, malformed, duplicate and unsupported target refusal before installed-state changes, plus update/rollback/state-preservation evidence. The full native, guarded boot and PHP/WordPress fixtures remain Debian 13 only; Debian 12 reports those scopes **NOT_RUN** and instead requires exact new-native-Apply refusal with unchanged state/network policy and inert supplementary units. A local-sourced bundle and synthetic default route are **not** foreign field evidence. Inactive offline phases have process-complete network-attempt traces; active update tests cannot claim the identical zero-network-attempt property.
- The separately authorized [Debian 12 real-host lifecycle driver](../scripts/qa/host-debian12-proxy-lifecycle.py) consumes only the ordinary base QA archive and a target/boot-bound private manifest. Its complete archive identity must match successful exact-candidate CI before field execution. It requires an initially uninstalled host, real installed-service Proxy Only requests with independent nonce/origin observations, actual selected-upstream loss without Direct fallback, state-preserving Disconnect/reconnect, same-artifact reinstall, uninstall and exact task-owned cleanup. Distinct-manager updates and intentionally broken-unit rollback fixtures remain isolated-CI-only evidence and are not generated or executed on the field host. It does not change global routes, firewall, DNS or APT, and its local VLESS peer does not establish foreign egress, TUN, all transports, performance or physical reboot acceptance. Before/after network, Docker and resolver observations are non-atomic; fresh management SSH checks belong to the controlling operator. - [APT](../scripts/qa/host-apt-only.sh) and [WordPress/FastCGI](../scripts/qa/host-wordpress-fpm.sh) fixtures test genuine selected **Proxy Only** application behavior and outages, **not** transparent TUN. APT needs trusted native executables/method paths, effective-policy and credential controls: reject shadow executables, hostile `Dir::Bin`/`RootDir` redirects and unsafe combined-update forms before selected-path execution; generic `HTTP_PROXY` is insufficient. Its explicit invocation puts the native action first, for example `server-connect apt -- apt-get update -q` or `server-connect apt -- apt-get install -y package`. Options before that action and ambiguous short-option groups are refused; supported value-taking options and canonical quiet forms remain available after the action. This binds strict update handling to the same action native APT dispatches and prevents grouped configuration options from escaping preflight. Native acquisition explicitly disables FTP, SSH/RSH and mirror+FTP for its own subprocess after rejecting caller or inherited method overrides; it verifies both the original and stricter effective policy. The Debian 12 stock-layout exception requires trusted host/tool observations and does not attest the loaded acquisition library. The guest's unsigned `trusted=yes` test repository is never production guidance. WordPress' `WP_PROXY_*` settings are disposable **QA-only** pool-local configuration, never a customer-site change.
- [Native TUN APT/Git](../scripts/qa/tun-native-apps.py) and [WordPress/PHP-FPM](../scripts/qa/tun-wordpress-fpm.sh) use a **separate genuine sing-box TUN/VLESS in a disconnected disposable guest**, with independent TCP-origin source and native Direct-counter evidence. The genuine installed WordPress HTTP API uses **no `WP_PROXY_*` constants, PHP proxy environment or process-specific capture**: a fresh Direct positive control, a separate selected-VLESS success, and an upstream-loss fail-closed request are each checked against the independent origin witness and active TUN policy. These synthetic addresses and guest-only checks do **not** establish real Iranian/foreign field routing, physical host SSH/aaPanel/website safety, production Smart Routing Apply, or real reboot recovery.
- [Large TCP/UDP TUN path probe](../scripts/qa/tun-payload-wire.py) exercises 512 KiB bidirectional TCP, a 1300-byte UDP **data body** (1335-byte framed request and 1347-byte framed response, excluding IP/UDP headers), a synthetic reduced IPv4 VETH underlay MTU 1280 against a TUN MTU 1400, a locally rejected oversized DF datagram, and upstream-loss no-Direct-leak witnesses. - [Supervised native lifecycle](../scripts/qa/host-supervised-product-tun.sh) extends only that same disconnected fixture. - Native product ownership evidence must distinguish **supported disjoint changes**, which survive successful Off, from **overlap or missing proof**, which retain resources and report uncertainty. The fixture adds foreign objects while active, then checks same-link address, route/rule collision and nftables-child conflicts. Its POSTROUTING check must use the actual selected output interface and leave forwarded traffic with its existing owner. This is a packet-transit witness, not a new end-to-end application or arbitrary forwarding acceptance claim. A deliberately removed guard/drop identity requires stopped core, retained routing footprint and `UNCERTAIN`, not automatic route deletion. Pause only the authenticated installed timer/executor while holding the existing manager lock; verify idle units with no queued jobs, release the lock before product commands or traffic, and check the same pending operation before and after the probes. A `/run` runtime mask does not freeze a higher-priority installed `/etc` unit ([systemd unit load path](https://www.freedesktop.org/software/systemd/man/257/systemd.unit.html)). Track temporary QA pause ownership before stopping either unit. After partial failure, rearm only the authenticated original journaled operation under its applicable state proof; a completed Off operation's late QA receipt needs exact independent finalization and native baseline proof before its own removal, without restarting the disarmed timer. During explicit missing-guard remediation only, an authenticated guard-kind receipt and the same guard-origin stop-requested operation may accept the original executor's failed/failed exit-code state as quiescent when its PIDs, job and tracked cgroup are empty and the owned core is inactive. This does not reset failure bookkeeping or establish healthy guard availability; normal pending/off and completed-state checks remain strict. Report any unresolved cleanup. Recovery after deliberate QA resumption is explicit installed-executor evidence, distinct from autonomous scheduling. A completed Direct/off transition is not an active/degraded no-leak measurement.

## Delivery sequence

The next meaningful network milestone is **one real independently guarded Smart Routing TUN vertical slice** with two-sided Iran Direct/foreign VPN proof, no per-job workstream, protected SSH/foreign-client website replies and genuine DNS/UDP/IPv4/IPv6 truthfulness. Then finish Runtime Guard and host safety, official/mirror/offline package acceptance and representative field checks. A signed release must not advertise unimplemented features.

A failed or incomplete required test remains open in its owning Issue and exact PR/CI evidence. The complete runtime recovery rules are in [SAFETY-RECOVERY.md](SAFETY-RECOVERY.md); packaging trust in [OFFLINE-DISTRIBUTION.md](OFFLINE-DISTRIBUTION.md).
