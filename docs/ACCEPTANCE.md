# Acceptance and evidence contract

**Goal:** Prove the delivered features of [PROJECT-SPEC.md](PROJECT-SPEC.md) on exact source, build, package and network environments. This document owns the **test matrix and proof threshold**; Issues own unfinished work and PR/CI/Release artifacts own particular runs and verdicts.

## Evidence rules

- Identify the exact commit, release/archive hash, official upstream sing-box version, OS/kernel/architecture, actual active profile path (without secrets), relevant host baseline, required duration, results and rollback evidence.
- Record **PASS / FAIL / NOT_RUN / UNSUPPORTED** explicitly. Never infer a real foreign VPN path from a healthy sing-box process, Direct internet request, code test, Docker loopback, a Windows client or synthetic network outage.
- Evidence levels differ: **source/unit**, **disposable installed Linux guest**, **independently observed real Iran/foreign field path**, **authenticated distributable artifact**, and **separately authorized production rollout**. A lower level never implies a higher one.
- Privileged/network-affecting implementation needs exact-candidate fault and safety tests and **fresh author-separated high-assurance review**. Production server changes and publication require their own applicable Owner approval. No real customer server is an initial test host.

Owner-approved **proportional recovery** requires representative evidence for normal Disconnect, unexpected Core exit, safe restoration of Direct/off, and common selected-path failures. It does not demand exhaustive fault permutations or a guarantee against arbitrary simultaneous privileged host writers. Unknown ownership still preserves third-party resources and is reported uncertain; unsupported paths are not labeled PASS.

### Exact-candidate hybrid-IP and dual-stack acceptance (current development)

For a candidate that incorporates the two-source Iran country policy, independently verify the **actual pinned source hashes, CIDR intersection, excluded second-source-only cloud addresses, operator `--iran-coverage dbip` fallback, stored CIDR VPN precedence, offline package source/license pair and refusal of missing/tampered members**, plus old installed-release removal/update. Country agreement alone does not prove current physical location. Future GeoSite Direct activation requires authenticated DNS/IP correlation and separate negative source-spoofing evidence.

For a candidate that suppresses AAAA by default when selected IPv6 egress is unverified, prove **ordinary unforced dual-stack HTTPS** on actual WordPress API/download, aaPanel-equivalent and a large download on the exact real selected foreign VPN path, *not* merely `curl -4`. Verify normal A responses and a properly scoped empty AAAA response through the **actual installed TUN**; test literal IPv6 failure and independent underlay no-leak packet counters, before/after selected exit failures; verify protected public SSH and established HTTP replies. On an environment with genuinely working selected exit IPv6, test explicit opt-in positive IPv6 DNS/literal TCP/TLS and failure/no-leak. Mark unavailable global/provider IPv6 **UNSUPPORTED/NOT_RUN**, never a PASS. Retest Core SIGKILL, short provider outage, real reboot and original kernel restoration on the exact candidate before stable release.

## Test lanes and field-regression lessons

These are **different evidence levels**, not interchangeable versions of a PASS:

| Lane | What it can establish | What it cannot establish |
| --- | --- | --- |
| Unit/source and rooted namespaces | Compiler, safety, packet witnesses and negative cases on their tested source | Installed host lifecycle, physical foreign provider/SSH |
| Current Debian 12 installed-host CI lane | Package/install/update and Direct/Proxy Only; current Native `connect-smart` installed acceptance; standalone native `default`/`bypass_iran` DNS/IPv6/MTU packet lab; **actual installed official-Core/Guard/VLESS/Direct/TCP/UDP/DNS/Off and missing-HTTPS automatic fallback**. Each outcome counts as `PASS` only on exact successful candidate CI | Disconnected synthetic fixtures do not prove healthy selected public HTTPS, physical Debian 12 native activation, production hosts, third-party providers or broad IPv6/PMTUD |
| Current Debian 13 installed-host CI lane | Actual installed `connect-smart`/official-Core/Guard selected VLESS, Direct, TCP/UDP/DNS, synthetic missing-HTTPS fallback and exact owned restoration (score only after exact successful CI) | A healthy real selected-provider HTTPS, physical foreign/management paths, arbitrary hosts and production safety |
| Historical Debian 12 and 13 Incus native installation evidence | Native installed-lifecycle/packet/ownership results **only for the recorded source, artifact and guest identities** ([original Issue #2 evidence](https://github.com/AChWorks/server-connect/issues/2#issuecomment-6766057958)) | Transfer of those results to the present CI selector, changed source revisions or physical-host acceptance |
| Historical Debian 13 QEMU/legacy guarded trial | Narrow v4-journal/fresh-SSH and foreign-client witness regression | Acceptance of the newer official-Core-native lifecycle |
| Independently authorized nonproduction physical host | Only the exact installed candidate/real packet paths and original management/hosting behavior actually measured | Other source revisions, untested transports or production permission |

The current installed-host selectors are in [`test-installed-host.sh`](../scripts/qa/test-installed-host.sh). [Historical installed-host CI](https://github.com/AChWorks/server-connect/actions/runs/44326932048) predates the Debian 12 packet-lab extension and recorded Debian 12 native-positive `NOT_RUN` versus Debian 13 supervised positives; it cannot validate a later source revision. The separate original Debian 12 source-generated DNS lab **alone** cannot establish installed activation. The added [installed native trial](../scripts/qa/host-installed-native-connect.sh), when successful on an exact candidate, actually runs the installed `connect-smart` Core/Guard and restores all five kernel inventories, but **still cannot establish physical field acceptance or successful selected HTTPS**. **Both OS versions have separate historical Incus evidence**, but that proof is bound to its original revisions. The retired legacy trial has no Debian 12 admission path; only the current Native `connect-smart` acceptance decides current support. The Debian 12 native early reply hook originally failed to verify its own table because `nftables` 1.0.6 lists owned sets before its chain rather than after, unlike 1.1.3; the revised exact two-layout receipt/claim parser preserves its original strict structure, fingerprint and generation/handle checks. A second Debian 12 installed Health Guard failure came from older nft rendering TCP as numeric `meta l4proto 6 counter` instead of `meta l4proto tcp counter`; the strict read-only policy inspector admits both true TCP forms only when the counter and redirect belong to the **same expected output-NAT-chain rule**, not a matching counter in `output_prematch`; UDP/unknown or counterless output redirects fail closed. An earlier terminal or traffic-diverting output NAT rule cannot hide behind a correct later TCP redirect; scoped Core underlay/local/IPv6/MPTCP exceptions remain valid. The current candidate must pass exact-head installed-host CI before this is counted as accepted. **Do not claim fixed or accepted on Debian 12 until the exact candidate CI completes.**

**Two non-negotiable physical regressions:** An established foreign SSH session passed Direct/off positive controls but was reset during native Apply. Merely marking existing conntrack replies was insufficient when connections predated conntrack or appeared reversed; an **exact accepted TCP socket four-tuple** guard preserved application-level SSH replies without exempting all new outbound traffic to that foreign IP. Separately, Core `SIGKILL` left real orphan RPDB rules: safe cleanup must require its specific current-boot ownership/consumed operation claim and refuse foreign/aliased table references. Source and isolated regressions exist, but **retake physical old/new SSH, website replies and crash recovery on the exact candidate** before claiming field acceptance. See the [physical evidence and fixes in Issue #3](https://github.com/AChWorks/server-connect/issues/3#issuecomment-6987698584) and [original bound field proof in Issue #2](https://github.com/AChWorks/server-connect/issues/2#issuecomment-6807595141).

When a guard returns verified Direct/off, it is a **network restoration** success, not proof that a formerly blocked foreign route now works. Do not repair orphan policy by flushing another owner's tables; report `UNCERTAIN` if exact ownership cannot be proved. Capture the relevant native and provider-side packet paths independently; use `tcpdump -p` for old TUN-trial captures so the test does not change link flags.

## Registry-country data boundary

A pinned **DB-IP Country Lite geolocation estimate (October 2026)** is bundled for offline read-only inspection via `smart-routing-data`, with independently tested canonical IPv4/IPv6 prefixes, sorting, overlaps, special-purpose rejection, strict metadata, a pinned source-archive digest and a **separate source-code pin of the exact derived-prefix digest** (not merely a self-rehashed JSON member). **Attribution: [IP Geolocation by DB-IP](https://db-ip.com), licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).** Project modifications: extracted IR country-code records from DB-IP Lite CSV and converted source IP intervals into deterministic CIDR lists. DB-IP Lite is a reduced-coverage, imperfect estimate of IP country, not proof of the current origin, reachability or route of any packet; therefore `safe_for_geographic_routing` and `activation_ready` remain **false**. A reproducible local archive generator verifies exact pinned source bytes (including a checksum cross-check against the published mirror) and an offline installed Debian 13 guest verifies that inspection never changes network state. A source hash is not a publisher signature, and checking one source never establishes the precision of all its country assignments. Trustworthy update, rollback, rule precedence and real Iranian/foreign field route validation in the release matrix remain open.

The historical parallel TUN candidate compiler and its synthetic
IPv4/IPv6/Host/SNI exception caps were retired. The accepted Native
compiler uses saved operator rules, strict canonical IP/CIDR/domain
validation and deterministic priority ordering, without importing
a second experimental routing policy or its artificial quotas. Native
VPN-only domain rules are not independently authenticated DNS-to-IP
correlation, so a user-supplied Host or SNI must never create an
unapproved Direct exemption. Registry attribution and live
Iran-vs-foreign path acceptance are separate requirements.

**Historical candidate containment:** an earlier unpublished PR #57 iteration temporarily embedded RIPEstat Country Resource List data, whose service terms prohibit repackaging without written permission. That dataset was replaced with explicitly redistributable CC BY 4.0 DB-IP Lite data **before merge**; never reintroduce the RIPEstat payload into distributable artifacts without explicit written rights. Prior public Git objects may remain accessible by immutable SHA even after branch-history replacement.

## Existing tests and their limits

Use this as a **navigation index for reproducible regressions**, not a record of which SHA passed. Actual PASS/FAIL/NOT_RUN, logs, artifact hashes and independent review verdicts belong to the relevant PR/Actions and linked Issue comments. Every case below is **bounded to its own source, guest, profile and network**.

- **Package and installed-host gate:** [installed systemd workflow](../.github/workflows/installed-host-qa.yml), [installed scenarios](../scripts/qa/test-installed-host.sh), [minimal online guest](../scripts/qa/test-online-minimal-host.sh), and [workflow-policy tests](../scripts/qa/test-installed-workflow-policy.py) exercise source/bundle identities, old/new versioned local installation, target-specific Debian 12/13 lifecycle, prerequisites and native policy restoration. The privileged `pull_request_target` workflow must stay trusted-base, same-repository and **exact-candidate-identity** constrained; it is not fork or production execution authority.
- **Nonproduction field driver:** [Debian 12 lifecycle driver](../scripts/qa/host-debian12-proxy-lifecycle.py) validates its **current complete archive contract**, host/boot/source identity and private evidence without inheriting installed user/profiles. It is **not** a substitute for an independently observed selected Smart Routing field path. Earlier fixture drift must not silently pass a stale inventory.
- **Proxy Only applications:** [APT](../scripts/qa/host-apt-only.sh), [WordPress/FastCGI](../scripts/qa/host-wordpress-fpm.sh) and [Debian 12 lifecycle tests](../scripts/qa/test-debian12-proxy-lifecycle.py) prove explicit proxy-aware behavior, normal Direct coexistence, outage and cleanup. Application proxy settings are **not** proof of transparent host-wide routing.
- **Transparent TUN applications:** [APT/Git](../scripts/qa/tun-native-apps.py), [WordPress/PHP-FPM](../scripts/qa/tun-wordpress-fpm.sh) and [large-payload wire tests](../scripts/qa/tun-payload-wire.py) validate ordinary proxy-unaware traffic and independently observed selected vs Direct paths in disconnected guests. The fixture includes 512-KiB TCP and bounded UDP/underlay MTU cases; it does **not** certify arbitrary fragmentation, PMTUD or real providers.
- **Field-selected tunnel (source-only isolated netns):** [field harness](../scripts/qa/field-selected-tun-netns.sh) guards its temporary namespace/VETH/forwarding resources with independent finite cleanup and leaves the host product Direct/off. Its `--split-exception` and `--wire-matrix` modes separate raw DNS, public Direct overrides, selected VPN, endpoint outage, positive-control packet witnesses and 512-KiB HTTPS. Original host SSH/network restoration must be separately checked. DNS leaks must be attributed to exact observed application questions, not unrelated bootstrap/getent packets; oversized DNS/UDP is **inconclusive** if the Direct positive control already fails.
- **Native dual-stack packet witnesses:** [current Native compiler](../internal/sc/smart_native_policy.go) and [IPv6 wire fixture](../scripts/qa/tun-ipv6-wire.py) test bounded IPv6 Direct/VPN/exception and fail-closed behavior on synthetic guests. Their observations cannot establish physical geolocation, broad fragmentation or PMTUD.
- **Read-only native host inspection:** `host-preflight --with-nftables` with `host-drift` observes native route/rule/link plus validated versioned `nft -j` schema and private policy digests. Changed/malformed foreign policy is reported unverified; a read-only observation is **not atomic host reservation, trustworthy route ownership or Activation Guard**.
- **Resource ownership primitives:** [native nftables CAS test](../internal/sc/smart_tun_native_nft_native_linux_test.go), [native recovery tests](../internal/sc/smart_native_recovery_linux_test.go), [Docker kernel crash/foreign-bridge test](../scripts/qa/host-native-docker-recovery.sh) and [installed native lifecycle](../scripts/qa/host-installed-native-connect.sh) validate real official-Core ownership and exact cleanup. The obsolete precreated addressless/gVisor TUN experiment was retired: its object lifecycle differs from the selected Native `auto_route`/`auto_redirect` path. Unreceipted effects and overlapping foreign changes remain `UNCERTAIN`, not grounds for broad resets.
- **Installed official-Core native lifecycle:** [installed native connect-smoke and health-failure trial](../scripts/qa/host-installed-native-connect.sh) uses the actual systemd-installed `connect-smart` command in separate Debian 12 and 13 disconnected Docker guests. A real synthetic VLESS peer, explicit Direct rule, independent underlay packet counters, UDP/TCP/DNS and foreign hosted replies precede explicit Disconnect with five exact kernel inventory checks. A second run has **no authenticated selected HTTPS target**, so the real Health/Recovery roles must independently return to Direct/off. This is deliberately an unhealthy-selected-path recovery test, **not** evidence that selected HTTPS is healthy, the provider has failed, or the latest revision is physically accepted.
- **Official-Core native DNS and IPv6 policy:** [native DNS-policy lab](../scripts/qa/host-native-dns-policy.sh) compares both `default` and `bypass_iran` with **positive-controlled UDP/TCP port-53** private/explicit Direct/VPN/country-estimate ordering, selected resolver path and provider-loss no-Direct-leak observations. It also checks bounded IPv6 UDP payloads (1352/1353/2400 bytes) under a reduced guest underlay MTU. A large virtual TUN MTU or healthy HTTPS alone does not prove general IPv6 fragmentation, PMTUD or real Iranian DNS reachability.
- **Current Native Health and Guard:** [installed Native acceptance](../scripts/qa/host-installed-native-connect.sh), [Health policy tests](../internal/sc/smart_native_health_linux_test.go) and [lifecycle tests](../internal/sc/smart_native_lifecycle_linux_test.go) check actual recovery roles, selected HTTPS evidence, no-Direct-leak failure and precise Direct/off. Synthetic QA certificates and peers are not proof of a healthy external selected provider; fresh management SSH and physical recovery still require separate field evidence.
- **Historical persisted records:** The source still strictly recognizes and safely abandons exact unarmed v1 or recovers owned v2/v3 records. A v4/unknown old operation is not migrated or reactivated: fresh Native admission and installation must refuse uncertain retained evidence. [Boot recovery](../scripts/qa/test-activation-boot-qa.sh) remains an independent guest test, not an old-binary physical upgrade proof.
- **Host coexistence and fault injection:** real native guest cases must distinguish non-overlapping foreign changes (preserve after Off) from overlapping/unknown ones (refuse cleanup). They exercise new outbound to a foreign hosting client's IP while established inbound replies remain Direct, actual forwarding without stealing other owners' traffic, source-bound fresh IPv6 neighbors, Core SIGKILL orphan rules, interrupted policy deletion and stale recovery state. A Docker restart is **not** physical power loss; the old disconnected Docker `/run` mount-propagation workaround was **fixture-specific**, not an OS deployment recommendation.

**Still unproven by synthetic/install QA alone:** authenticated Iranian geography, arbitrary foreign providers/physical-host control paths, all TCP/UDP/DNS/IPv6 and payload cases, modern native Physical reboot/power-loss, installed identity under every upstream transport, independent publisher trust and production safety. See the [test matrix](#required-release-matrix), [host-specific recovery contract](SAFETY-RECOVERY.md) and current owning Issues for actual field acceptance.

## Delivery sequence

The next meaningful network milestone is **one real independently guarded Smart Routing TUN vertical slice** with two-sided Iran Direct/foreign VPN proof, no per-job workstream, protected SSH/foreign-client website replies and genuine DNS/UDP/IPv4/IPv6 truthfulness. Then finish Runtime Guard and host safety, official/mirror/offline package acceptance and representative field checks. A signed release must not advertise unimplemented features.

A failed or incomplete required test remains open in its owning Issue and exact PR/CI evidence. The complete runtime recovery rules are in [SAFETY-RECOVERY.md](SAFETY-RECOVERY.md); packaging trust in [OFFLINE-DISTRIBUTION.md](OFFLINE-DISTRIBUTION.md).
